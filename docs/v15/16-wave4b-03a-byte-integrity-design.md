# V15-W4B-03A — Original document byte integrity design

Status: DESIGN CANDIDATE; implementation not authorized by this goal. Base `fe503ab83e0f927facaca69457d8e9684dee20d1` fetched from `origin/agent/v15-w4b-02-review-2ajw4xh6`. Isolated detached worktree. No production/schema change, commit/push or runtime test rerun.

`OCR_SOURCE_BYTE_INTEGRITY=DEFERRED_BLOCKING_VALIDATED_IMPORT` remains in force. Design completeness does not remove this blocker or imply human design approval, clinical validation or import acceptance.

## Goal Capsule and decision

C3/R3, complex ceiling, root HIGH for storage/DB/TOCTOU invariants and MEDIUM for documentation. Root sole writer; two bounded read-only risk reviews cover DB and Security independently. Scope: source audit, local-storage byte snapshot and provenance contract, proposed additive migration, race matrix, compatibility/rollback and implementation sequence. No provider replacement, UI/import/Pet writes/sharing expansion.

Choose server-generated immutable document-version records backed by private create-only byte snapshots, SHA-256 and counted length, plus append-only attempt/result input receipts. Rehash and consume the same bounded in-memory byte snapshot for a trusted adapter invocation, outside PostgreSQL transactions. A stored digest is evidence of the bytes observed at a declared capture point; it is not evidence of an earlier OCR execution or original upload authenticity.

Keep accepted171974/171975 and existing OCR job uniqueness/lifetime/retry rules. Only a newly enqueued job whose source version was established before its first claim may acquire the new byte binding. Existing jobs remain metadata-only. A successful old job cannot be rerun or relabelled; fresh OCR needs a fresh explicitly uploaded document/new document ID and new job. No automatic document duplication, current-version replacement endpoint or new rerun API is proposed for03A. This conservative compatibility choice avoids changing the accepted single-job-per-document API. If product later requires re-OCR on the same document ID, authorize a separate versioned-job API/schema contract; do not silently drop the existing UNIQUE(document_id).

## Four independent assertions

| Assertion | Required evidence | Does not establish |
|---|---|---|
| SOURCE_BYTES_VERIFIED | version capture event, exact original doc/Owner/Pet relation, trusted storage version, SHA256/actual count verified against a server snapshot at recorded time | Past execution input, upload-time authenticity for legacy files, clinical correctness |
| OCR_RESULT_SOURCE_BOUND | exact version+attempt+accepted immutable result, trusted byte-input transport receipt for full consumed input matching digest/count, current fenced completion; evidence class ACTUAL_BYTE_INPUT | Owner decision, OCR accuracy, clinical validation |
| OWNER_CONFIRMED | CONFIRM event for exact candidate predecessor revision/textVersion/hash/result | Byte verification or clinical validation |
| CLINICALLY_VALIDATED | separately authorized future validation/import authority and record | Implied by none of the other assertions; not implemented |

Assertions are independent evidence predicates, not a linear status enum. Evidence remains historical while eligibility is a current conjunction of valid source, result binding, exact Owner decision and future validation rules. Deletion/archive/revocation can deny current eligibility without erasing prior evidence.

Simulation remains SIMULATED_METADATA_ONLY even if a verified version exists. No current simulation result is labelled OCR_RESULT_SOURCE_BOUND.03A can prove storage and transport mechanics with an instrumented test consumer, not real extraction/accuracy. A future trusted adapter must actually receive/consume the verified byte input under the binding contract before its result qualifies. Merely including a digest in request metadata or trusting a provider-returned hash is insufficient.

## Trusted capture and storage contract

1. Authenticate current Owner, exact active Pet and allowed PASSPORT/HISTORY; never accept a client path, URL, digest, version ID or length as authority. Retain10MiB ceiling; reject empty/truncated/oversize source and inconsistent declared length.
2. For a new upload, trusted capture is the exact bytes received and subsequently verified from durable snapshot; count actual buffer/stream bytes and compute SHA256. MIME/name are descriptive and not byte identity. For legacy capture, explicitly record OBSERVED_EXISTING_AT_CAPTURE and the observation interval/coherence evidence; it is not the historical original upload. SOURCE_BYTES_VERIFIED then describes only the exact new snapshot; OBSERVED_SEQUENCE_ONLY does not certify a coherent original document version.
3. Create server UUID version in a **flat private snapshot namespace**, create-only O_EXCL, no user path segments, no shared cross-Owner deduplication. Mode0600 during write; file+directory durability barriers before publication; seal read-only, reopen through hardened descriptor helper and verify exact digest/count. A failure publishes no DB version. Snapshot key is private; digest is never a public URL/token.
4. Deployment precondition: fixed canonical root and its parent hierarchy owned/protected from untrusted directory renames, symlinks and writes; only controlled publisher can create snapshots, worker has read-only access. Current singleton Nest app+worker does not establish separate deployment identities: specify and verify publisher/worker UID/GID, root/ancestor ownership/modes/ACL and mount permissions before enabling the feature; a privileged publisher can chmod/rewrite and remains a trusted principal. This is a rollout prerequisite, not an already audited operating guarantee. Helper validates root policy, final O_NOFOLLOW, regular file, expected ownership/mode and no hardlink aliases. Do not inherit the current realpath/final-no-follow sequence as a complete sandbox. If this precondition cannot be established, fail closed and choose a separately reviewed immutable-version object store; no unsafe fallback or new provider integration in03A.
5. DB insert uses short transaction, locks active Pet then exact Document when no job exists, rechecks captured metadata/generation and soft-delete state. Version record and capture event commit together after durable bytes. New upload may commit document/version/audit atomically in this DB transaction. The original storage file is not overwritten. Copying an existing source only records observed-now provenance. Read-only sealing is an application/storage protocol, not protection against OS root; rehash at every trusted use is still mandatory.
6. DB/COMMIT failure may leave a private unpublished object. Retry does not assert success from its filename. Idempotent publication reconciles server capture operation ID/context/digest. A task-owned sweeper may remove only unattached temporary objects after age and DB reconciliation; never delete published versions or raw/history. Filesystem+PostgreSQL are not a single ACID transaction; durability-before-reference plus orphan quarantine is intentional.
7. New upload concurrency must recheck Owner/archive after disk I/O. Legacy capture rechecks old storage_key/type/size/current scope using observed generation and locks; stale capture loses CAS. Snapshot readback proves the copied byte sequence, not that an unlocked legacy inode had that entire sequence at one instant. Same-length changes can evade stat checks or create a torn read. A coherent legacy source-version capture requires independently established write exclusion/immutable source generation during reading; absent that evidence, OBSERVED_EXISTING_AT_CAPTURE records only the observed byte sequence over a start/end interval and cannot qualify as a coherent original source version for validated import. Prefer fresh upload of explicit Owner-provided bytes. Detected mutations reject capture; undetected absence of mutation is never inferred. Metadata stable does not imply content stable; never retroactively match this capture to old OCR.

Implementation may add nonsemantic composite UNIQUE keys needed for FKs to existing tables; no existing rows/uniqueness/lifecycle triggers are changed. Add a deferred-at-COMMIT DB success invariant for every job with a byte-source sidecar: its SUCCEEDED result must have the matching accepted attempt receipt; ACTUAL_BYTE_INPUT requires its exact result binding, while SIMULATED_METADATA_ONLY requires an honest simulation receipt and no actual byte binding. Guard must cover job, result, receipt and binding changes and reject an old binary committing bound-job metadata-only success. Validate contexts using row locks, not only presence. This is a new integrity guard, not a rewrite of the old lifecycle function.

No mutable current-version pointer is needed in03A: one frozen version is bound to each newly queued job. Multiple capture observations can exist per document, but none rewrites its original storage metadata or existing job binding. Negative events invalidate current use and future import; they never remove historical receipt evidence. New upload is the bounded path to a new OCR job after a terminal legacy/successful job.

## Execution, races and failure protocol

A. Enqueue transaction: establish published version first; job/source binding inserted atomically, using existing per-document idempotency. Concurrent capture may create private or unused versions but only one job wins. Returning an existing legacy job must disclose metadata-only evidence, never attach a receipt or infer verified status.

B. Claim transaction: retain accepted SKIP LOCKED/fenced lease/lifetime3attempt logic and job→Pet→Document lock order; read frozen binding/version valid events. Old metadata-only jobs continue their accepted simulation path, with no new verified labels. No filesystem hash/provider call under a PostgreSQL transaction.03A changes to bound-job code require targeted existing lease/retry regression; sticky unaffected sharing/review gates remain reused.

C. After COMMIT, hardened helper opens exact version, fully reads into bounded private Buffer, counts and hashes the same bytes. Fail before provider on mismatch/missing/unsafe path/negative event/source change. Capture transport wrapper exposes a one-shot stream from private verified bytes, with copied chunks so provider mutation cannot alter the retained snapshot. No later path reopen supplies provider bytes. Provider execution stays outside transactions. Full-consumption receipt and input digest/count are generated by the trusted adapter at the full delivery/consumption boundary, not merely Readable.push or producer-side emission; partial input, timeout/abort or adapter that ignores bytes cannot earn ACTUAL_BYTE_INPUT binding. A receipt proves trusted input delivery under adapter contract, not semantic parsing or OCR accuracy.

For documents whose legacy download source is a separate mutable file, current metadata equality alone is insufficient: compare its current bytes to the frozen source tuple before invocation and final completion; mismatch/missing/replacement appends a negative source event and rejects. A fresh upload should publish one canonical byte object referenced by document storage metadata and the version, avoiding divergent duplicate authorities. The new namespace must remain compatible with current private download resolution; any shared primitive change requires targeted Wave4A byte-delivery tests without grant/authorization changes. A later version-specific Owner inspection contract must name exactly the bound version, never silently display unrelated current bytes.

D. Finish preflight outside transaction: verify durable version remains available/intact; reject observed replacement/deletion/corruption. Metadata/context snapshots remain fenced by a short final transaction. Finish locks job→Pet→Document→version (and events)→attempt; checks current token/lease, exact frozen tuple, current valid source and trusted receipt. Raw result+candidate+receipt+result binding+job success commit atomically; simulated metadata results get no result byte binding. Final COMMIT/audit failure rolls everything back; unpersisted runtime receipt is never considered success. Stale worker cannot overwrite a newer receipt/result; invocation IDs do not bypass claim fencing. Never retry SOURCE_CHANGED as ordinary provider failure.

E. All negative-version event writers use the same version row lock; they either lock job→Pet→Document→version in order or take version only and never subsequently acquire upstream locks. No version→job/Pet/Doc lock inversion is allowed; finish either precedes their commit or rejects. Doc soft-delete/archive/ownership updates serialize against final scope locks. Accepted completed authorization may precede a later mutation; no claim of continuous authorization or eternal file availability. Filesystem cannot join PG locks: protected create-only namespace is required, bytes used are private verified snapshot, detected later corruption invalidates future use. Subsequent validated import must reverify availability/digest/current scope again; a prior result binding is historical evidence only.

F. Provider crash/abort/network adapter failure closes descriptors/streams, releases Buffer and leaves only fixed error codes. Existing lease recovery and attempt bound remain. Physical missing/deleted/replaced/unverifiable objects remain import-ineligible. An identical-byte replacement detected by local file-instance observations is quarantined; inode/mtime are diagnostics, never canonical identity or historical proof. Privileged undetected tampering is outside the trusted-host model and must not be described as cryptographically prevented.

Down migration refuses destructive drop. No old trigger is removed. Rollback disables all OCR claimers/workers, including old binaries, and new publishers; retain version/receipt/event data and snapshots. Restoring old binaries is safe for reads only while OCR claimers remain disabled. Producer shutdown does not drain already bound queued/running jobs: old claim() selects them and its metadata-only finish() could otherwise strand immutable success. Resuming old claimers requires an independently reviewed complete drain/quarantine/exclusion of bound jobs and the DB fail-closed success/receipt invariant, not merely sidecar-ignore tests; stop historic pre-W4B01 worker binaries to avoid old direct-Pet writes. Restore verification must rehash snapshot bytes before new trusted use; restore test/Pilot evidence is not executed here. Retention/deletion policy for medical byte snapshots needs separate approval before operations;03A introduces no physical purge or promised retention duration.

## Alternatives and explicit W4B03B prerequisites

Rejected: metadata-only hashes; trusting MIME/size/ETag/provider-returned digest; hashing then reopening path for provider; assuming same descriptor prevents in-place writes; editing old source_identity/results/CONFIRM events; automatically promoting old jobs; dropping UNIQUE(document_id); public pre-signed URLs or arbitrary provider fetch; storing document blobs in PG as an unrequested storage migration. Separate object-store immutable versions are a feasible alternative if protected local publication cannot satisfy deployment prerequisites, with a new storage adapter contract and review.
