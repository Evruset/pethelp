# Future real OCR adapter acceptance contract

Design gate only; no provider implemented or enabled. TEST_CONSUMER proves backend mechanics only. SIMULATED_METADATA_ONLY must have zero consumed bytes, no consumed digest and no actual-source binding. Current trusted receipt origin is test-only; a future production origin requires separately reviewed additive contract, privileges and allowlists. An environment flag, provider name or successful request cannot confer trust.

A candidate adapter must provide stable implementation/provider identity and version, transport/API version and unavailable provenance explicitly absent. Define the trusted boundary that receives exactly the verified immutable source Buffer, its source version, SHA-256 and actual length. Count/hash the full input at that boundary and bind receipt to job, exact leased attempt, source version and immutable extraction/result identity. Prove the downstream extraction actually consumes those bytes rather than filename/metadata, cached unrelated text or a second mutable fetch. For remote providers, independently establish immutable request/object version and response correlation; upload success alone is not consumption proof. Bound media/byte sizes, timeouts and response sizes; retain no public download URL or storage identifier in responses/logs.

Test successful full consumption, zero/partial consumption, duplicate/reordered callbacks, wrong version/digest/length/result identity, source changes between capture/read/execute/finish, provider errors, timeout, cancellation, process death and COMMIT failure. Close streams/resources and cancel transport on every denied/failed path. Provider execution occurs outside PostgreSQL transactions. Lease fencing rejects expired/stale workers; results and receipt/binding commit atomically, and retries cannot overwrite terminal results. Receipts cannot be supplied by ordinary application users or guessed from metadata.

Immutable provenance must link exact document version → verified bytes → actual execution receipt → immutable raw result/candidate → exact Owner-confirmed revision and correction version. Rehashing legacy bytes cannot prove an earlier OCR execution; fresh verified source and new execution are required. Owner confirmation remains non-authoritative text approval, not clinical validation or sharing eligibility.

Accuracy acceptance is separate from transport mechanics: approved representative consented/redacted datasets, ground truth, provider/version-specific quality/error metrics, unsupported formats and language/handwriting limitations, failure handling and human acceptance are required. Never invent accuracy thresholds or claim test consumer/simulation demonstrates real extraction. Privacy/data residency, processing agreements, secret handling, retention, restore and operational isolation need independent approval and real-environment evidence.

Validated import remains prohibited until source-byte integrity, production execution provenance and a separately approved clinical-validation/import/sharing authority contract are complete. Keep OCR_SOURCE_BYTE_INTEGRITY=DEFERRED_BLOCKING_VALIDATED_IMPORT. No UI, import or medical-history write is implemented by this contract.
