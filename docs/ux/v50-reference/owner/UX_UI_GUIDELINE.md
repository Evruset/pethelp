# VetHelp Owner / Aggregator V50 — единый UX/UI guideline

## Цель
Owner/Aggregator — **fast decision interface**. Он должен помогать владельцу быстро принять безопасное и понятное решение, а не выглядеть как лендинг, справочник клиник или плотная B2B CRM.

## 1. Density modes

### Decision Compact
Для:
- каталог клиник;
- выбор врача;
- выбор времени;
- review заявки;
- альтернативное время.

Правила:
- spacing 4 / 8 / 12 / 16 / 24 px;
- page padding desktop 20–28 px;
- один главный decision surface на viewport;
- карточка результата отвечает: **кто / когда / сколько / где / почему подходит**;
- вторичное доказательство не должно дублировать уже объяснённое;
- controls остаются не меньше 44 px там, где требуется точное действие.

### Care Normal
Для:
- главной;
- моих записей;
- деталей записи;
- карточки питомца.

Больше воздуха, но первый viewport отвечает на вопрос: **что делать сейчас?**

### Content Relaxed
Для:
- дневника;
- документов;
- профиля;
- образовательного/справочного контента.

Допускается более спокойная вертикальная композиция.

## 2. Decision hierarchy
1. Срочность / безопасный следующий шаг.
2. Ближайшее доступное действие.
3. Время + цена + дорога + подтверждение.
4. Почему вариант подходит конкретному питомцу.
5. Доказательства: capability, отзывы, свежесть данных.
6. Детали и дополнительный контент.

## 3. Карточка клиники в каталоге
Не витрина. За 2–3 секунды должны читаться:
- название;
- время в пути;
- ближайший слот;
- цена;
- формат подтверждения;
- краткое «почему подходит Барни».

Фото и бейджи поддерживают решение, но не заменяют его.

## 4. Карточка клиники
Первым идёт compact decision summary. Затем — доказательства.
Не повторять цену, trust и статусы в 3–5 разных больших секциях.
Consent на дополнительные услуги — часть визита, а не обязательная часть выбора клиники.

## 5. Booking
Progressive disclosure:
`выбрать время → проверить → отправить → ждать authoritative confirmation`.
Проверка страхования не является обязательным шагом базовой записи.
Нельзя визуально смешивать выбранный слот и подтверждённую запись.

## 6. Alternative slot
Экран отвечает только на четыре вопроса:
- почему исходное время недоступно;
- что предложено;
- какие ещё варианты есть;
- что будет после выбора.
Внутренние backend/fencing объяснения не должны конкурировать с решением владельца.

## 7. Behavioral UX
Give-to-Get / WIIFM — короткая полезная причина действия, не отдельный рекламный hero.
Не использовать искусственный scarcity, FOMO, ложные счётчики и давление.

## 8. Responsive
- desktop: list + compact decision context / sticky summary;
- tablet: один основной столбец + contextual panel;
- mobile: один task flow, sticky/clear CTA, без параллельных колонок.

## 9. Что изменено в этой версии
- уменьшена landing-page масштабность главной;
- каталог стал плотнее и быстрее для сравнения;
- добавлен единый decision summary клиники;
- скрыты дублирующие price/trust/consent блоки на этапе выбора;
- выбор врача уплотнён;
- базовый booking сокращён до 2 шагов без обязательной страховки;
- review и alternative slot очищены от повторяющихся статусных объяснений;
- сохранена разница между B2C fast-decision и B2B operational density.
