# VetHelp Clinic V50 — единый UX/UI guideline

## Цель
Clinic Portal — desktop-first операционное рабочее место. Он должен быть **плотным, но читаемым**, быстрым и action-first. Он не должен ощущаться как маркетинговый сайт, растянутое мобильное приложение, BI-дашборд или тяжёлая МИС.

## 1. Density modes

### Compact — рабочие экраны
Используется для:
- Сегодня / очередь действий;
- Записи;
- Расписание;
- Пациенты;
- telemed queue.

Правила:
- базовый spacing: 4 / 8 / 12 / 16 / 24 px;
- page padding desktop: 18–24 px;
- panel padding: 12–14 px;
- gap между рабочими поверхностями: 8–10 px;
- H1: 28–34 px, без hero-подачи;
- controls: минимум 44 px;
- рабочая поверхность занимает доступную ширину;
- нельзя оставлять искусственный max-width, если справа образуется пустая зона.

### Normal — карточка пациента / визит
- чуть больше смыслового разделения;
- 10–14 px panel gaps;
- основная информация и действия видны в одном viewport;
- документы, ограничения и следующий шаг не прячутся в декоративные карточки.

### Relaxed — настройки / профиль клиники
- допускается больше воздуха;
- но без hero-блоков и landing-page композиции.

## 2. Информационная иерархия
1. Что требует действия сейчас.
2. Текущий статус / SLA / конфликт.
3. Основное действие.
4. Контекст для решения.
5. Вторичные настройки и аналитика.

## 3. Карточки
Карточка используется только для отдельной смысловой сущности. Не оборачивать каждую строку, показатель или текст в самостоятельную карточку.

## 4. Расписание
На стандартном desktop должно быть видно минимум 6–8 часов рабочего дня и 3–5 сотрудников, если это позволяют данные. Строка времени не должна быть декоративно высокой.

## 5. Таблицы и очереди
- строки компактные;
- аватары небольшие;
- статус и основное действие сканируются за секунды;
- подробности открываются рядом/drawer, а не раздувают каждую строку.

## 6. Touch / accessibility
Плотность не достигается уменьшением hit-area: интерактивные элементы остаются минимум 44×44 px. Цвет не является единственным носителем статуса.

## 7. Behavioral UX
WIIFM / Give-to-Get используются как короткая подсказка результата действия, а не как отдельный большой рекламный блок. На рабочих экранах behavioral copy не должно конкурировать с очередью задач.

## 8. Responsive
- desktop: полный журнал / split view / drawer;
- tablet: рабочая поверхность + overlay detail;
- mobile: task list + full-screen detail, без принудительного desktop-grid.

## Изменения этой версии
- убран 980px cap у главной рабочей панели;
- summary + WIIFM собраны в одну горизонтальную обзорную полосу на desktop;
- уменьшены page/header/panel spacing;
- tabs используют всю ширину;
- уплотнены таблицы, пациенты и рабочие панели;
- расписание стало ниже по вертикали и показывает больше рабочего дня;
- сохранён минимум 44 px у действий;
- управленческие страницы оставлены спокойнее, чем operational screens.
